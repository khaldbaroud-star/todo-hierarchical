# ملخص مشروع: تطبيق المهام الهرمي (To-Do List)

> هذا الملف يلخّص كل ما تم إنجازه حتى الآن، ليُستخدم كسياق كامل عند بدء محادثة جديدة مع Claude.

---

## 1. نظرة عامة على المشروع

تطبيق ويب تقدمي (PWA) شخصي لإدارة المهام، بميزة جوهرية: **المهام يمكن أن تكون فردية أو مركّبة (تحتوي مهام فرعية متعشّشة بأي عمق)**. المستخدم مطوّر يعمل بمفرده على Windows، بدون تسجيل دخول، أوفلاين أولاً مع مزامنة عبر Cloudflare. كل التواصل بخصوص المشروع يتم بالعربية.

---

## 2. الحالة الحالية: كل مراحل الخطة الأصلية الثمانية مكتملة عدا النشر النهائي

| المرحلة | الحالة |
|---|---|
| 1. البنية الأساسية محلياً (تعشيش، تقدم تصاعدي، اكتمال تلقائي) | ✅ مكتملة |
| 2. قائمة اليوميات (ربط/فك ربط لأي نوع مهمة، تصاعدي) | ✅ مكتملة |
| 3. منطق الضياع التلقائي (rollover) + الترك اليدوي | ✅ مكتملة (منطق + شارات بصرية) |
| 4. شاشة الإحصائيات (3 فئات + فلتر زمني) | ✅ مكتملة |
| 5. تحويل PWA فعلي (Manifest + Service Worker) | ✅ مكتملة (عبر vite-plugin-pwa) |
| 6. Cloudflare Workers + D1 (المزامنة) | ✅ مكتملة (مزامنة كاملة عند الطلب) |
| 7. الاستيراد/التصدير + UUID الجهاز يدوياً | ✅ مكتملة |
| 8. النشر عبر GitHub + Cloudflare Pages | ⬜ **لم تبدأ بعد — هذه الخطوة القادمة** |

**إضافة غير مخطط لها أصلاً**: تصميم احترافي كامل (نظام ألوان/خطوط، عنصر "حلقة النمو" البصري المميز، إدخال سريع على شكل سطر).

## 3. البنية التقنية

- **الواجهة الأمامية**: React + Vite + Dexie.js (IndexedDB) + vite-plugin-pwa
- **الخلفية**: Cloudflare Workers + D1 (منشورة فعلياً)
- **الخطوط**: Markazi Text (عناوين)، IBM Plex Sans Arabic (نص عام)، IBM Plex Mono (أرقام)
- **رابط الـ Worker المنشور فعلياً**: `https://todo-worker.khaldbaroud.workers.dev`
- **قاعدة بيانات D1**: الاسم `todo-db`، المعرّف `3493aa06-eb4b-4e41-846c-62e92388a62c`

## 5. قواعد منطقية جوهرية تم تطبيقها بدقة

1. **التقدم من الأوراق فقط**: `calculateProgress` يجمع كل الأوراق (leaf tasks) بأي عمق، بوزن متساوٍ.
2. **الاكتمال التصاعدي ثنائي الاتجاه**: عند وصول مركّبة لـ 100% تكتمل تلقائياً؛ وإذا أُضيفت لها لاحقاً ورقة جديدة غير مكتملة (حتى بعد اكتمالها)، **تتراجع تلقائياً** عن حالة "منجزة" (تصحيح تم اكتشافه أثناء التطوير).
3. **الربط بالليوميات موحّد للجميع**: أي مهمة (فردية/مركبة/جذرية/فرعية) قابلة للربط والفك يدوياً. ربط/فك مركّبة **تصاعدي بالكامل** — يشمل كل فروعها المتعشّشة تلقائياً.
4. **الترك (Abandon) لا يمنع اكتمال الوالد تلقائياً بشكل كامل**: مهمة متروكة تبقى محسوبة في مقام أوراق والدها لكن غير محسوبة كمكتملة — فالوالد لن يصل 100% تلقائياً طالما توجد ورقة متروكة بداخله (قرار تصميمي اتُّخذ لعدم وجود تحديد صريح بالبرومبت الأصلي).
5. **الضياع أزلي**: أي تأخر عن `original_due_date` ولو بيوم واحد يُصنَّف "ضائعة" للأبد بغض النظر متى أُنجزت لاحقاً، حتى لو تم ترحيلها (rollover) لاحقاً لتاريخ جديد.
6. **المنجزة تختفي بصرياً**: أي مهمة تكتمل تختفي من القائمة النشطة (في كل مستوى من الشجرة وفي كل صفحة) وتنتقل لقسم قابل للطي "المهام المنجزة".
7. **المزامنة last-write-wins على مستوى الخادم**: يعتمد كلياً على `updated_at`. **قيد معروف**: لا يوجد تتبّع حذف (tombstones) بعد — حذف مهمة محلياً لا يُبلَّغ للخادم.

## 6. ما تبقّى / الخطوة القادمة

**المرحلة 8 (لم تبدأ)**: رفع المشروع على مستودع GitHub، ثم ربطه بـ Cloudflare Pages للنشر التلقائي المستمر لمجلد `frontend/` تحديداً (مع تجاهل `worker/` عن هذا الربط، لأنه يُنشر بشكل منفصل عبر `wrangler deploy`).

**أشياء مؤجَّلة بقرار واعٍ (وليست أخطاء)**:
- الأيقونات (`icon-192.png` / `icon-512.png`) مؤقتة تماماً — تصميم رمزي بسيط لغرض الاختبار فقط
- لا يوجد تتبّع حذف في المزامنة (tombstones) — الحذف المحلي لا ينتشر للخادم أو للأجهزة الأخرى بعد
- تعديل UUID الجهاز يدوياً من الإعدادات يُحفظ لكنه الآن فعّال 100% (المزامنة الفعلية تعتمد عليه)
